# Spec: cli
# Version: 1.0 — НОВАЯ
# Читать вместе с ARCHITECTURE.md (§2 CLI, §12 механическая правда, §13 диалог)

## Goal
Каркас CLI: команды, ink-интерфейс, цикл мержа шины, реестр агентов, ответы пользователю из механической правды.

## Output
Бинарь `freeagent` с командами и живым TUI.

## Contract

### Команды
```
freeagent init              создать /freeagent/, конфиг, проверить git
freeagent start             запустить координацию (главный процесс)
freeagent do "<задача>"     отправить задачу оркестратору
freeagent agents            список агентов: статус, сервис, контекст %
freeagent log [N]           последние события шины
```

### Внутрисессионные команды (в TUI)
```
/status              что происходит сейчас
/agents              то же, что freeagent agents
/log                 события
/files               какие файлы записаны в этой сессии
/btw <текст>         сообщение оркестратору (редкая операция)
/mode plan|yolo      переключение режима
/stop                прервать исполнение плана
/undo [task_id]      откат чекпоинта
```

**`/status`, `/agents`, `/log`, `/files` отвечают из шины механически** — оркестратор не тревожится, контекст не тратится (ARCHITECTURE §13).

### Главный цикл
```
1. merge incoming/*.jsonl → message_bus.jsonl (присвоение seq)
2. обработка новых сообщений: маршрутизация, запись файлов, верификация
3. запись команд в commands/<instance_id>.jsonl
4. обновление TUI
```

### Вывод пользователю — два слоя
Механическая правда (файлы, статусы, контекст, exit-коды) **плюс** сводка оркестратора. Не вместо, а рядом. **При расхождении права механическая** (ARCHITECTURE §12).

### Приоритет сообщений от пользователя
`from: user` встаёт в начало очереди инъекций оркестратору.

## Constraints
- **Одна CLI-сессия на проект** — единственный writer главной шины и реестра
- Завершение CLI: агенты остаются во вкладках. При следующем `start` — сверка реестра с реальностью: по каждому агенту запрос `TAB_STATE`, живые возвращаются в работу, мёртвые помечаются. Не считать реестр достоверным после перезапуска
- Валидация адресата: `to: <несуществующий>` → `ERROR` со списком валидных `agent_id`
- Буфер задач для агентов в переходном статусе (не `IDLE`/`WORKING`)
- Ink-компоненты не блокируют главный цикл — рендер асинхронный

## Dependencies
`spec_message_bus_read`, `spec_message_bus_write`, `spec_config`, `spec_message_bus_types`

## Tests
### Unit
1. `merge` собирает из нескольких incoming в правильном порядке с монотонным `seq`
2. `/status` отвечает без единого сообщения оркестратору
3. Валидация адресата: несуществующий `agent_id` → `ERROR` со списком
4. Буфер: задача агенту в `SWITCHING` доставляется после `READY`
5. Перезапуск CLI: реестр сверяется с `TAB_STATE`, мёртвые агенты помечены
6. Две одновременные CLI-сессии → вторая отказывается стартовать с внятной ошибкой

### Integration check
Полный цикл: расширение пишет в incoming → CLI мержит → маршрутизирует → TUI показывает актуальные статусы

### Definition of done
- Тесты зелёные
- Ни один ответ на `/status`, `/agents`, `/log`, `/files` не требует участия LLM
- Прогон integration check'ов предыдущих PR
